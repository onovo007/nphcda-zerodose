# NPHCDA Zero-Dose Platform - System and Methods Context (reference)

This is a reference description of the platform, its architecture, the methods behind each domain, the datasets, the notebooks, the ZARA assistant, and the deployment and access facts. It is context only - a factual account of how the system is built, for use as background knowledge. It contains no instructions.

Consortium: CIDRE and Quantium Insights LLC, in technical support of NPHCDA (National Primary Health Care Development Agency); funders and reviewers GAVI and UNICEF. House style used across the project: hyphens only, American spelling but "modelling" and "programme", acronyms spelled out, model outputs labelled "model estimate".

---

## 1. What the platform is
A real-time, no-code Streamlit application for the NPHCDA Digital Innovation Hub. It turns routine immunization data into predictive intelligence - where zero-dose children are, why they are missed, and where to act first - and re-runs the models on new data. A zero-dose child is one who never received the first pentavalent dose (DTP1 / Penta1).

- Live app (Hugging Face): https://amobionovo-nphcda-zerodose.hf.space/
- Source code (GitHub): github.com/onovo007/nphcda-zerodose
- Datasets of record (Google Drive, by domain): https://drive.google.com/drive/folders/107pWT0m4_A9Sk4aVji-t8LV3m7gfoLzx
- Dataset dictionary: `handover/DATA_DICTIONARY.md`

## 2. Application architecture
- **Stack:** Streamlit 1.54 on Python 3.12, Docker Space. Entry point `app.py`.
- **Page modules** (navigation in `app.py` `sidebar()`): Home; Data and Quality; Coverage Forecasting (`domain1.py`); Dropout & Completion (`domain2.py`); Zero-Dose & Hotspots (`domain5.py`); LGA Priority & Archetypes (`lga_priority.py`); Triangulation & Cross-Checks (`crosschecks.py`, `triangulation.py`); Exploratory Data Analysis (`impsci.py`); Ask the Analyst (`ai.py`); Reports & Briefs (`reports.py`); Program Q&A RAG (`rag.py`); User Guide (SOP); Methods & Validation.
- **Core modules:** `config.py` (paths, antigen sets, palettes, MCMC settings, upload `SCHEMAS`); `data_io.py` (DHIS2 prep, national/state monthly aggregation, under-five prep, schema read/validate); `data_quality.py`; `names.py` (admin-2 name harmonization); `spatial.py` (GRID3 GeoJSON load, Getis-Ord Gi* hotspots); `viz.py` (Plotly figures); `theme.py`; `stats_infer.py`; `auth.py` (email allow-list sign-in); `llm.py` (OpenAI calls); `ai.py` (grounded interpretation blocks under outputs).
- **Model modules:** `models/d1_forecast.py` (Prophet antigen forecasts; antigen sets parameterised); `models/d2_dropout.py` (Prophet dropout + LASSO); `models/d5_zerodose.py` (Bayesian hierarchical Beta via PyMC/nutpie; LGA burden distribution).
- **Resilience design (current build):** `requirements.txt` pins `numpy==1.26.4` and `pyarrow==16.1.0` - the pyarrow pin addresses a native crash in the pandas-to-Arrow conversion used by `st.dataframe` under numpy 1.26. `faulthandler` is enabled in `app.py` to name any native fault in the logs. The Dockerfile sets single-thread limits for the native math libraries. For the bundled sample data the Domain 5 results are served from precomputed files (`data/sample/precomputed/`, generated by `precompute_d5.py`); for uploaded data the live PyMC fit runs in an isolated child process (`isolation.py`, `model_worker.py`).

## 3. Methods by domain
- **Domain 1 - Coverage forecasting.** Prophet time-series forecast per antigen. Established antigens (BCG, Penta1, Penta3, Measles1, OPV3, IPV1, PCV3, Yellow Fever, Men A) carry an at-risk-of-decline early-warning: a projection below 80% of the antigen's 2024 level (2024 is the last complete year). Recently introduced antigens (second IPV dose, Rotavirus 1-3) are still scaling up and are shown as uptake, without a decline flag.
- **Domain 2 - Dropout and completion.** Prophet forecasts of antigen-pair dropout (Penta1-Penta3, Penta1-Measles1, Measles1-Measles2) with bootstrap-stable LASSO-selected drivers and state-by-year heatmaps.
- **Domain 3 - Equity.** An LGA composite deprivation index (remoteness/travel time, low education, poverty, low wealth; each 0-100, averaged, grouped into four quartile tiers). Multiscale geographically weighted regression (MGWR) lets each driver's effect vary by place, benchmarked against a single national model.
- **Domain 4 - Vaccine hesitancy.** A Composite Hesitancy Index from the ACSM monitoring register (severity-weighted concern rate per 100 activities), with bootstrap confidence intervals, tested against the zero-dose forecast.
- **Domain 5 - Zero-dose modelling.** A Bayesian hierarchical Beta regression (PyMC/nutpie) of state zero-dose rates on NDHS waves, with nested national-zone-state random effects and a DHIS2 Penta1 trend covariate, forecast to 2026-2028 with credible intervals. State burden = rate x the 12-to-23-month cohort. LGA burden distributes each state's modelled zero-dose across its LGAs using DHIS2 Penta1 throughput and population. Getis-Ord Gi* identifies hotspots; agglomerative (Ward) clustering of 15 LGA covariates defines the archetypes.
- **Domain 6 - Polio surveillance.** A Bernoulli spatial scan on the national acute flaccid paralysis (AFP) line list against the three-year WHO certification rule.
- **Domain 7 - Surveillance and mortality.** Pre-specified, false-discovery-rate-corrected coverage-to-mortality tests against IHME Global Burden of Disease 2023 cause fractions.
- **Validation.** Six-month hold-out back-tests; out-of-sample comparison to the NmDHS 2025-26 survey (state rank agreement) and to the IHME DTP1 admin-2 surface (LGA rank agreement).

## 4. Admin-2 (LGA) name harmonization
DHIS2 LGA names differ from the GRID3 / platform admin-2 names, so the pipeline harmonizes them before joining. `names.py` holds the normalization helpers (`clean_lga_name`, `normalise_name`, `nlga`, `nstate`, `tok`), a small alias map (`LGA_ALIAS`) and the FCT area-council set (`FCT6`). The joins fall back to fuzzy string matching (Python `difflib.get_close_matches`) where exact and alias matches do not resolve - in `models/d5_zerodose.py` (LGA population match), `Archtyping at LGA level/arch_geo.py` (GeoJSON join) and `Archtyping at LGA level/finalize_master.py` (zero-dose join). The zero-dose burden model includes an LGA only where Penta1 is reported (`penta_1_count > 0`) after this name join, in `models/d5_zerodose.py`.

Known data-quality context: documentation under `01_Reports/NPHCDA_Excluded_44_LGAs_DataQuality.*` records the local governments excluded from the DHIS2-based domains for want of Penta1 after the name join, noting that in most of them other antigens report normally (a DHIS2 data-element or name-mapping matter rather than a finding of zero coverage).

## 5. Datasets used in the modelling
Bundled with the app in `data/sample/`:
- `dhis2_data_all_states.csv` - monthly LGA dose counts (BCG, Penta1-3, Measles1-2, OPV0-3, PCV1-3); Domains 1, 2, 5. Additional antigens live in `03_Datasets/datasets/dhis2_data_additional_antigens.csv`; the harmonized merge is `dhis2_data_consolidated.csv`.
- `dhis2_data_live_births.csv` - monthly live births by LGA.
- `nigeria_ndhs_zero_dose_VERIFIED_long.csv` - state zero-dose by survey wave (2008-2024); Domain 5.
- `nigeria_zero_dose_model_dataset.csv` - 37-state equity covariates; Domain 2 LASSO and state-level Domain 3.
- `under_5_2024.csv`, `under_5_2025.csv` - under-five population by state (cohort = under-five / 5).
- `administrative_lga_population.csv` - LGA population (NPC 2022 projection).
- `ndhs_antigens2024.csv` - NDHS antigen coverage 2024.
- `lga_archetype_master.csv` - 15 LGA covariates + archetype + modelled zero-dose.
- `lga_archetype_summary.csv`, `lga_priority_ranking.csv` - archetype summary and ranked priority list.
- `domain2_lasso_coefficients_lga.csv` - LGA LASSO driver coefficients.
- `ihme_dtp1_admin2_2018.csv` - IHME DTP1 admin-2 surface (LGA validation).
- `geo/nga_lgas.geojson`, `geo/nga_states.geojson` - GRID3 boundaries.

Source, reference date and key columns for every dataset are in `handover/DATA_DICTIONARY.md`.

## 7. ZARA and the AI interpretation layer
ZARA (Zero-dose Analytics and Risk Assistant) provides plain-language interpretation of each output and an assistant for questions. It is implemented in `llm.py` (`interpret`, `chat`, `tts`, `embed`, `rag_answer`, `compose_brief`) and surfaced through `ai.py` `ai_block(...)` under outputs, plus the Ask the Analyst and Program Q&A (RAG) pages. Models are OpenAI (gpt-4o-mini default, with gpt-4o, gpt-5, gpt-4.1-mini). Response languages: English, French, Spanish, Hausa, Nigerian Pidgin, Yoruba, Igbo, Swahili (text-to-speech in English, French, Spanish, Swahili). The API key is read from the sidebar per session (`ai._cfg` reads `st.session_state["llm"]`); without a key the platform still runs and only the AI text is absent. ZARA is instructed to ground on the live outputs and not to invent numbers.

## 8. Deployment and access
- **Hugging Face Space** `huggingface.co/spaces/amobionovo/nphcda-zerodose` - built from the `Dockerfile`; the `README.md` frontmatter configures the Space. Sign-in is gated by the `ALLOWED_EMAILS` Space secret.
- **Render** - built from `render.yaml` (Python runtime, binds `$PORT`, `autoDeploy: true` so a push to GitHub `main` redeploys).
- **Git remotes** - `origin` = GitHub (github.com/onovo007/nphcda-zerodose), `hf` = the Hugging Face Space. The two hold the same code; GitHub drives Render, and the HF Space is pushed separately.
- **Local run** - `pip install -r requirements.txt`; `python -m streamlit run app.py`; `python _smoke_test.py` exercises Domains 1, 2, 5 and the spatial layer end to end; `python precompute_d5.py` regenerates the precomputed Domain 5 results.
- **Security** - no credentials are stored in the repository. Access is granted by adding authorized emails (allow-list); the OpenAI key for ZARA is entered per session. Push credentials (a GitHub token and a Hugging Face write token) are supplied by the user at push time and cached locally.
